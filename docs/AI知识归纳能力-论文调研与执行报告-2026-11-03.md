## 2. 文献地图：AI 整理归纳知识点的能力现状

> 本节只讲「对 AI Edu 有直接动作价值」的结论，每条标注论文与可操作启示。完整论文清单在 §7。

### 2.1 「课程认知」是新提出、且现有基准没有覆盖的能力

**K12-KGraph**（arXiv 2605.09635，2026）把 LLM 在教育里的能力拆出一个新维度：不只是「答对题目」，而是「理解课程知识是如何被组织的」——**课程认知（curriculum cognition）**，具体包括：先修链、概念分类体系、实验-概念关联、教学排序、视觉呈现。

该论文从人教版官方教材构建知识图谱，用 **9 类节点**（Book / Chapter / Section / Concept / Skill / Experiment / Exercise / Figure / VisualElement）和 **14 类关系**表达课程结构。基准测试（K12-Bench，23,640 题）显示：即便是强模型，Gemma-4-31B-IT 只有 **46% 精确匹配**，其中 **Prereq（先修）与 Neighbor（相邻关系）是最难的两个任务族**。

**启示**：AI Edu 知识网络目前只有 1 类节点（`Concept`）和 6 类关系（`knowledge.py:34-41`），节点没有类型、没有层级。文献表明「先修关系」恰是最难、也最能区分模型教学能力的部分，而当前 `prerequisite_of` 只占 24%，且没有「Skill」「Exercise」这类与练习/实践相关的节点类型。**如果目标是让知识网络支撑教学排序，节点类型与关系类型都需要扩展。**

另外：K12-KGraph 用 KG 引导的 SFT 数据（2,300 样本）在 GaokaoBench 和 EduEval 上**超过 8 个主流指令微调语料库的等量子集**。这说明**结构化课程数据比泛指令数据更有样本效率**——对 AI Edu 的 `TrainingRecord` 导出（测试版训练）有直接参考价值：把「大纲-章节-验收标准」的结构对齐数据导出，可能比泛化对话样本更有训练价值。

### 2.2 概念图生成：六类方法与两类验证手段

**Generative Large Language Models for Knowledge Representation: A Systematic Review of Concept Map Generation**（arXiv 2509.14554，2025）综述了 28 篇 LLM 生成概念图的研究，归纳出六类方法：

| 方法类别 | 说明 | 对 AI Edu 的适用性 |
|---|---|---|
| Human-in-the-loop 系统 | 人主导，LLM 辅助 | `review_proposal` 已有雏形，但 `knowledge_proposals` 表实测 **0 条记录**，未被使用 |
| 弱监督学习 | 需标注数据 | 短期不适用 |
| 微调领域 LLM | 需领域语料 | 长期可考虑（见 2.1 KG 引导数据） |
| 预训练 LLM + 提示工程 | 纯 prompt | **当前 AI Edu 用的就是这个** |
| 混合系统（KB 集成） | 结合已有知识库 | 可结合 `disciplines.py` 学科画像 |
| 符号 + 统计模块化框架 | 规则 + 模型 | 对应 `COMPLIANCE_GUARDS` 的确定性校验思路，可扩展到结构校验 |

验证手段分两类：**定量指标**（precision / recall / F1 / semantic similarity）和**定性评估**（专家评审 / 学习者反馈）。综述指出四大挑战：**有效性、可解释性、多语言适应性、课堂整合**。

**启示**：AI Edu 目前对知识图谱只有「无环、无自环、无重复」这类极弱校验（实测自环 0、重复三元组 0、先修环 0——这部分是健康的），但**没有任何定量指标**（如边集的 precision/recall，相对教程正文可核验的边）。「相关」桶占 32.2% 说明关系判别能力弱。建议至少加两个确定性指标：**关系类型分布健康度**（`related` 占比 > 30% 即预警）和**边-正文可定位率**。

### 2.3 知识点抽取：分层与粒度是核心，本体约束是保障

**Knowledge Point Entity and Relation Extraction based on Pre-training Model in Education Resources**（2023，预印本）在「机器人学」教材上做了三级知识点（一/二/三级）+ 先修关系抽取，并用增量预训练弥补预训练模型在该领域的知识不足。

**Automatic tagging of knowledge points for K12 math problems**（arXiv 2208.09867，2022）指出数学文本因含符号与公式，结构语义比一般文本复杂，直接套通用文本分类技术不满足知识点预测精度要求，提出基于标签语义注意力 + 多标签平滑的 LABS 模型。

**Human Evaluation of Procedural Knowledge Graph Extraction from Text with Large Language Models**（arXiv 2412.03589，2024）是**实践性教程最直接相关**的一篇：它用 prompt chaining 把自然语言流程抽取为**符合预定义本体的结构化知识**——具体抽取字段是**步骤（steps）、动作（actions）、对象（objects）、装备（equipment）、时间信息（temporal information）**。人工评估结论：抽取**质量**评分积极，但**有用性**评分较犹豫；在没有标准答案的抽取任务上，LLM 能力与人类相当。

**启示**：AI Edu 的 v2 `steps` 块只是一个 Markdown 字符串（`tutorials.py:243-247`），没有结构化字段。实践性教程的「步骤」如果拆成**动作 / 对象 / 装备 / 预期结果 / 验证方式 / 回退方式**六个字段，就能实现文献中的「本体约束抽取」，让 `check_structure` 对实践步骤做**确定性校验**（而不只是「非空」），也让知识网络能把「某步骤用到某工具/命令」作为关系边纳入图谱。

### 2.4 先修关系：反对称约束 + 双结构（先修 + 相似）

**ProPRL: Property-Aware Prerequisite Relation Learning in Educational Knowledge Graphs**（arXiv 2608.03006，2026）的核心贡献是处理先修关系学习中的两个问题：如何融合互补证据，以及**如何阻止同一个概念对在两个方向上同时得高分**。方法：概念-资源超图 + 有向学习行为图 → Pair-conditioned Gate 自适应融合 → **不可逆性约束（Irreversibility Constraint）**，用反对称正则项惩罚同一对概念在两个方向上同时高置信。

**KnowLP / GraphRAG-Induced Dual Knowledge Structure Graphs**（arXiv 2506.22303，2025）则指出有效学习路径需要**双结构**：先修关系 + 相似关系，二者互补；其 EDU-GraphRAG 模块自适应生成概念图，DLRL 模块缓解路径推荐中的「阻塞现象」。

**RPKT**（arXiv 2508.11892，2025）针对「学习者不知道自己不知道什么」（unknown unknowns）问题，用 LLM 做递归先修发现：从当前目标递归回溯未掌握的先修概念。

**启示**：AI Edu 实测有 **9 对同一类型双向边**（如 A→B 和 B→A 都是 `part_of`）。ProPRL 的反对称约束可以直接在 `upsert_relation`（`knowledge.py:361-415`）或图谱校验层落地：插入一条边时，若反向同类型边已存在，给较低置信并标记 `conflict`，或要求人工裁决。另外 AI Edu 已同时有 `prerequisite_of` 和 `contrasts_with`，结构与 KnowLP 的双结构思路一致——这点是做对了的，值得保持。

### 2.5 教程生成：执行式流水线是实践性教程的关键

**From Task to Tutorial: An Automated GUI Framework for Excel Tutorial Document and Video Creation**（arXiv 2509.21816，Microsoft，FSE 2026）是**实践性教程最核心的参考**。它首次实现了从自然语言任务描述端到端生成 Excel 教程，三阶段流水线：

1. **任务实例化（Task Instantiation）**：把模糊任务（如「做一个柱状图」）实例化成可执行的具体任务；
2. **自动轨迹采集（Automatic Trajectory Collection）**：**Execution Agent 真正在 Excel 里规划并执行任务，采集中间产物**（截图、单元格状态、UI 交互记录）；
3. **教程生成（Tutorial Generation）**：把执行轨迹转成结构化文档与视频演示。

评估协议覆盖 **18 个方面**，其中文档侧 11 项指标：Text–Image Mapping（图文对齐）、Clarity（清晰度）、Completeness（完整性）、Correctness（正确性）、Sequential Order（顺序合理）、Understandability（易懂）、Conciseness（简洁）、Task Completion（可完成任务）、Efficiency（效率）、Satisfaction（满意度）、Preference（偏好）。人工与 LLM 评估都确认教程质量高，某些方面接近或超过专家编写的材料。生产环境实测：在 Microsoft M365 Excel 中生成 **1,400 份教程**，作者时间减少 **99%**，上线后用户参与度提升 **9%**。

**SPROUT**（arXiv 2312.01801，2023）用 **tree-of-thought** 把编程教程创作拆成可探索的步骤，配合交互可视化让用户参与和修正生成过程，用户研究显示能产出更可靠、更可定制的教程。

**KEPP**（arXiv 2403.02782，2024）把概率化程序性知识图谱当作「教科书」，用于教学视频的流程规划，少量监督即达 SOTA。

**启示**：AI Edu 当前实践教程（`COMPUTER_CLI` 学科画像里「每个命令给出前置条件、预期输出与验证方式」）是**让模型凭想象写出操作步骤**，没有任何执行接地。From Task to Tutorial 的关键洞察是：**教程的可信度来自「真的执行过」**，不是来自模型的语言流畅度。AI Edu 不一定需要 GUI Agent 那么重——哪怕对 CLI 类教程，让模型生成的命令**真的在沙箱里跑一次**并记录实际输出，再让模型基于「预期 vs 实际」修正步骤，就是文献中轨迹采集的最小可行版本。

### 2.6 认知层级：Bloom 之外，CLI 需要「操作影响」维度

**CogTax: A Four-Level Cognitive Taxonomy for Command-Line Computing Education**（arXiv 2607.00140，2026）指出命令行教学有一个 Bloom 分类法完全没覆盖的维度：**执行后果（operational impact）**。它提出四层认知分类 = **max（认知复杂度 from Bloom，操作影响）**，操作影响分四级：observational（只读观察）/ reversible（可逆）/ structural（结构性改动）/ administrative（系统管理）。作者用 AST 特征 + 语义嵌入训练分类器，在 **585 条专家标注的 Linux/bash 命令**上达到 **89% 准确率**。

**启示**：AI Edu 的 `COMPUTER_CLI` 学科画像（`disciplines.py:25-58`）已有「危险命令必须标注风险与回退方式」这条要求，但只是提示词软约束，没有任何分级体系。CogTax 给出了一个**可直接借用的二维分层框架**：认知复杂度（对应 L1/L2/L3）+ 操作影响（新增维度）。四层操作影响可以直接映射到章节 `content_type` 或新增一个 `risk_level` 字段，并让大纲排序遵循「先只读后可写、先可逆后结构性」的原则——这正是 CogTax 论文总结的「教学排序依据」。

### 2.7 质量评估：结构性幻觉、LLM-as-Judge 的局限、教学能力基准

**Structural Hallucination in Large Language Models**（arXiv 2603.01341，2026）提出了一个对 AI Edu 直接相关的概念：**结构性幻觉**——LLM 输出的「关系组织被系统性扭曲」，而**句子级准确率完全检测不出来**。它在三个结构化领域做压力测试：Roget 词典重建的边集 F1 **低于 0.05**、Wikidata 传记字段幻觉率 **超过 93%**、文献引用遗漏率 **91.9%**、节点集 Jaccard 相似度 **0.028**、来源不匹配率 **超过 94%**。结论：**流畅不等于结构忠实**。该方法给出一个可复用的验证架构：知识图谱抽取 → 图相似度分析 → 中心性比较 → 引用完整性验证，可被用作「摄取前质量控制层」。

**ELMES**（arXiv 2507.22947，2025，华东师范大学上海智能教育研究院）针对「现有基准测的是模型知道什么，不是模型教得怎么样」，与教育专家共建了 4 个教学场景 + 细粒度指标（附录 A 有完整量规表）：

| 场景 | 与 AI Edu 对应 |
|---|---|
| Knowledge Point Explanation（知识点讲解） | `section` 阶段 |
| Guided Problem-Solving Teaching（引导式解题） | `feedback` 阶段 |
| Interdisciplinary Lesson Plan Generation（跨学科教案） | `outline` 阶段 |
| Contextualized Question Generation（情境化出题） | `extra_exercises` 阶段 |

其中「知识点讲解」的量规分三大维度：**角色扮演**（角色一致性、情感支持、知识掌握）、**教学策略**（教学方法适当性、内容设计适当性）、**个性化响应**（响应学习者画像）。「跨学科教案生成」有 16 个二级指标，包括**认知冲突设计**、**认知递进设计**、**闭环评估设计**、**内部一致性**等。

**TeachBench**（arXiv 2601.21375，2026）提出用「学生在多轮教学后的成绩提升」来测教学能力，关键限制是**把教师 Agent 限制在结构化知识点与例题上**以避免信息泄露。一个重要负面发现：**加入例题不一定提升教学效果，模型会转向针对例题的纠错**而非知识本身的传递。

**MCQG-SRefine**（arXiv 2410.13191，2024）用迭代自批评 + 自修正 + 对比反馈生成高质量选择题，并引入 LLM-as-Judge 替代昂贵的专家评估；但其 Limitation 明确指出**生成与评估能力不对等，自评估存在偏差风险**。

**LLM-as-Judge in Education: A Curriculum-Grounded Marking Pipeline**（arXiv 2606.17507，2026）给了一个分阶段流水线：识别主题/子主题/认知要求 → 装配可验证的权威上下文 → 生成题目专属量规 → 推导分数。它强调要把「课程意图」操作化为具体产物：**规定动词、成果描述、表现带描述符、术语表、评分准则**。

**启示**：AI Edu 的 `check_structure` 是纯结构检查（5 项），`COMPLIANCE_GUARDS` 只有 2 条正则规则，已有 `exam_check.py` / `exam_verify.py` 做试卷自检。**试卷有自检而章节没有**——这是不对称的。文献给出的方向是：结构校验（确定性）+ 量规评估（LLM-as-Judge，但生成与评估要分离，且要接地到课程产物）。ELMES 的指标表几乎可以直接搬进 `quality_report`。

### 2.8 提示词工程的反直觉发现：过度注入会降低质量

**Automated Educational Question Generation at Different Bloom's Skill Levels**（arXiv 2408.04394，2024）研究了 5 个 LLM 在不同提示词技术下的出题质量。关键发现：

- **信息过载显著降低质量，尤其是小模型**：把「技能解释 + 示例题 + CoT 指令」全部塞进去，性能反而下降；
- 最优组合是 **CoT + （技能说明 或 技能解释 或 示例题）三者之一**；
- **CoT + 示例题**能产出更多高质量题，但**牺牲 Bloom 层级遵循度**；
- **Bloom 技能解释 + CoT** 略降高质量题数，但**显著提升 Bloom 层级遵循度**；
- **自动评估不等同于人工评估**。

**Lost in the Middle: How Language Models Use Long Contexts**（TACL 2024，1,612 引）发现：语言模型对长上下文**中间位置**的信息利用率显著最低，**开头和结尾最高**，即使把相关信息明确放进去也是这样。

**启示**：AI Edu 的 `section()`（`prompts.py:782-878`）最多注入 11 个块，且当前顺序是：

```
学科 → 学习目标 → 已学过章节 → 本章大纲 → 验收标准 → 【硬约束】 → 挡位 → 能力层级
→ 材料 → 格式规范 → 教学宪章 → 教学决策 → 配套文件名 → 定向修正 → 截断说明
→ 双链规则 → 任务块 → 输出 schema → 内容块规范 → 元栏目禁令
```

「本次硬性约束块」在第 6 位（中段），而「教学宪章」——它内部声明了「系统与安全 > 硬性约束 > 本次任务特殊要求 > 教学导向 > 学习材料」这个优先级——排在第 10 位，**即优先级声明出现在它要排序的对象之后**。按 Lost in the Middle 的结论，硬约束当前位于信息利用率最低的位置。这是一个可低成本验证的假设：把硬约束前移到「学习目标」之后、并在输出 schema 后重申，做 A/B 对比即可。

同时，EduQG 的「信息过载降低质量」提示：AI Edu 可以做一次**块消融实验**——对同一目标，分别去掉「教学宪章」「能力层级」「教学决策」「配套文件名」各跑一次，用 §5 的量规打分，确认哪些块真的在提升质量、哪些只是消耗 token 和稀释注意力。

### 2.9 练习与支架：ICAP 两类工作示例 + 例题的副作用

**Adaptive Scaffolding for Cognitive Engagement in an Intelligent Tutoring System**（arXiv 2602.07308，2026）基于 ICAP 框架（Passive / Active / Constructive / Interactive 四级认知参与），把工作示例分成两类：**Guided examples**（引导型，引发 Active 参与）和 **Buggy examples**（错误型，引发 Constructive 参与）。在 113 名学生的逻辑学 ITS 中比较 BKT 与 DRL 两种自适应策略：**BKT 对低先验知识学生提升最大（帮他们追上高先验知识同伴），DRL 对高先验知识学生提升更大**。

**启示**：AI Edu 的 `extra_exercises`（`prompts.py:914-968`）已经有「### 一、易错辨析」这个栏目，本质上就是 **Buggy examples**——这是做对了的，且有理论支撑（Constructive 参与）。可以进一步做的：按 `L1/L2/L3` 能力层级调整两类示例的比例（L1 多 Guided，L3 多 Buggy），这正好与 ICAP 论文中「低先验知识需要 BKT 式保守策略」的发现吻合。

同时 **TeachBench** 的「例题不一定提升教学」是一个需要警惕的信号：AI Edu 的 `_deliverable_task` 和 `_TEACHING_TASK` 里「例题数量由知识难度决定，没有教学价值就不加」的克制原则**有文献支持**，值得坚持，甚至可以更激进——对 L1（基础理解）用户，示例的价值可能低于对 L3 用户，因为 L1 更容易被「例题特定纠错」带偏。

### 2.10 学习路径与知识缺口：交互日志是免费的证据源

**Detecting Knowledge Gaps from Conversational AI Interactions Using Curriculum Prerequisite Graphs**（arXiv 2606.10736，2026）把学生的对话提问映射到 GPT-4 抽取的先修知识图谱（few-shot 分类器，43 类达 80% 准确率），发现**提问量与自报难度显著相关**——不需要题库、不需要逐题判定对错，仅凭对话日志就能定位课程级知识缺口。

**PersonaPath**（arXiv 2609.18861，2026）区分了 Exercise-Centric（基于做题记录）和 Knowledge-Centric（基于概念掌握与先修结构）两种路径规划，指出后者才需要显式的学习者画像、掌握状态与先修知识结构。

**启示**：AI Edu 的 `chat_messages` 表已经存对话，知识网络已有概念节点，但没有把二者连起来。文献的结论是：**对话日志 × 先修图谱 = 不需要额外出题就能定位知识缺口**。这是一个低成本、高价值的组合——让 `reflection` 阶段（`prompts.py:1000-1009`）把对话摘要与该目标的概念节点一起送入模型，让模型判断「哪些概念因反复提问而需要重新讲解」。

### 3.2 十项缺陷，按影响排序

#### D1（P0）知识提取看不到教程正文

`_tutorial_context`（`knowledge.py:415-434`）为每个章节构建的上下文是：

```
{
  "section_id": s.get("id", ""),
  "title": s.get("title", ""),
  "prerequisites": [str(p) for p in s.get("prerequisites", [])],
  "explanation_headings": [b.get("heading", "") for b in s.get("explanation", [])][:6],
  "steps": [st.get("text", "") for st in s.get("steps", [])][:5],
}
```

这三个字段（`prerequisites` / `explanation` / `steps`）是 **v1 结构**的字段。
而 `_normalize_section_raw`（`tutorials.py:270-281`）产出的 v2 章节结构是：

```
{
  "title": ..., "purpose": ..., "content_type": ...,
  "content": content_blocks,          # <-- 正文在这里
  "key_takeaways": [], "common_errors": [],
  "prerequisite_refs": [], "exercises": [],
  "sources": ..., "mapping_criteria": ...,
}
```

**实测结果**（99 个有内容的版本，328 个章节）：

| 指标 | 值 |
|---|---|
| v2 结构章节（有 `content[]`） | **318 / 328（97.0%）** |
| v1 结构章节（有 `explanation` 或 `steps`） | **10 / 328（3.0%）** |
| 教程正文总字符数（`content[].body`） | **2,522,686** |
| 提取上下文每章节携带字符数 | **151** |
| 正文 → 上下文保留率 | **1.97%** |
| 正文文本出现在提取上下文中的章节数 | **1 / 328** |

也就是说：模型在做知识点归纳时，**实际只看到大纲的 `title` 与 `summary`（平均 151 字符），完全看不到正文**。
471 个概念不是从教程内容里归纳出来的，而是从章节标题与大纲摘要里猜出来的。

**衍生问题**：`context_fingerprint`（`knowledge.py:462-467`）基于 `_stable_context`（含 `explanation_headings` / `steps`）计算指纹，
而这两个字段对 v2 恒为空 → **正文重写后指纹不变 → 会被「unchanged_content」跳过，不会重新提取**。

#### D2（P0）关系 98.2% 自动确认，分级机制失效

`extract_from_tutorial`（`knowledge.py:600-611`）的确认逻辑是：

```
# 分级策略：教程明确解释（带章节锚点）自动确认；仅推测保持待核实
confirmed = bool(section_id)
```

提示词（`prompts.py:1050-1051`）要求「带 section_id 表示教程明确解释（会自动确认），纯推测则留空 section_id 并降低 confidence」。

**实测**：792 条关系中 **778 条 confirmed（98.2%）**，仅 14 条 `proposed`。置信度分布：≥0.7 的 688 条（86.9%），0.5–0.7 的 95 条，<0.5 的 9 条。

**原因**：模型几乎总会给 `section_id`——因为它本来就只知道标题和大纲摘要（D1），
把关系挂到一个已有章节上是零成本的。**D1 与 D2 叠加后，「confirmed」的真实含义退化为「模型自称有锚点」**，
不再是「教程正文支持这条边」。

#### D3（P1）概念无类型、无层级；`related` 占 32.2% 成兜底桶

`Concept` 模型（`models.py:250-267`）只有 `title` / `definition` / `domain_key` / `aliases` / `source_refs`，
**没有节点类型（node_type）、没有层级（level）、没有父节点**。

概念标题字符长度分布：**p10=6，p50=10，p90=15，max=45**。
这意味着「赋值语句」（4 字）和「当变量缺失时的显示分支处理逻辑」（19 字）是同一层节点，无法区分粒度。

关系类型分布：

| 关系类型 | 数量 | 占比 |
|---|---|---|
| `related` | 255 | **32.2%** |
| `prerequisite_of` | 190 | 24.0% |
| `part_of` | 180 | 22.7% |
| `applied_in` | 108 | 13.6% |
| `explains` | 33 | 4.2% |
| `contrasts_with` | 26 | 3.3% |

`related` 是信息量最弱的类型（代码 `knowledge.py:597-598` 中它是非法枚举的兜底值），
却占了三分之一。这说明模型在区分「这六种关系到底是什么」时能力不足——或者六类枚举本身不够贴合实际关系。

#### D4（P1）反对称违例 9 对

同一对概念在两个方向上有同类型边（如 A→B 和 B→A 都是 `part_of`）：**9 对**。

**健康的部分**：自环 0、重复 (from,to,type) 三元组 0、`prerequisite_of` 有向环 0。
说明 `upsert_relation` 的去重和无环设计是有效的，问题集中在「双向同类型」这一种。

**ProPRL**（arXiv 2608.03006）针对的正是这个问题，它的不可逆性约束（Irreversibility Constraint）
是一个反对称正则项，惩罚同一概念对在两个方向上同时高置信。AI Edu 可以用更简单的确定性版本：
插入一条边时检查反向同类型边是否存在，存在则把新边标为 `conflict`（状态枚举里已有这个值，`knowledge.py:44`），交人工裁决。

#### D5（P1）概念上限 12 触顶

提示词写死「最多 12 个」（`prompts.py:1048`），代码切片是 `data.get("concepts", [])[:30]`（`knowledge.py:546`）。

**实测**：4 个只跑过一次提取的教程，概念数分别为 **12、12、12、2**——**3 个正好停在 12**。
关系方面，单次提取的关系数是 12、11、5、4，均未触到「最多 20 条」的上限。

即：**概念上限确实在削顶**（每教程平均 14.9 个概念、中位 17 个，是多次提取累加的结果），
关系上限目前不构成瓶颈。

**附带不一致**：提示词说 12，代码允许 30。建议把提示词上限改为动态（`min(8 + 2 × 章节数, 30)`），
或把代码切片同步到 12，避免「模型被限制在 12 但系统本可接受 30」的浪费。

#### D6（P0）v2 章节的步骤可验证性零校验

`check_structure`（`engine.py:39-134`）的第 5 项检查「内容块与步骤规范」：

```
for step in s.get("steps", []):   # v1 结构
    total_steps += 1
    if not (step.get("expected_result") and step.get("verification")):
        bad_steps += 1
step_ok = bad_blocks == 0 and bad_steps == 0
passed = step_ok and (total_steps > 0 or any(s.get("content") for s in sections))
```

对 v2 章节：`s.get("steps", [])` 恒为空 → `total_steps = 0` → 该项检查退化为「内容块类型合法且 body 非空」。

而 `_TEACHING_TASK`（`prompts.py:668`）明确要求：
「`steps`：操作步骤，body 用有序 Markdown 列表，每步含操作、预期结果与验证方式」。

**结果**：这条要求没有任何机器校验能发现违反。对实践性教程（`COMPUTER_CLI` 学科画像）
「每个命令给出前置条件、预期输出与验证方式」同样没有任何校验。

**对比**：`exam_check.py` / `exam_verify.py` 已经为试卷实现了自检机制——
试卷有校验而章节没有，这是一个不对称。把「步骤结构化 + 确定性校验」搬进 `check_structure` 是自然的扩展。

#### D7（P2）掌握度闭环零证据

`mastery_for_concept`（`knowledge.py:633+`）的设计是「掌握状态只由真实任务证据推导」：
尝试过 → 练习中；低辅助完成 → 已掌握；无 → 缺证据。

实测 `practice_tasks` = 3，`attempts` = **0**。

即：**471 个概念目前没有任何掌握度证据，`mastery_for_concept` 对全部概念返回 `no_evidence`**。
设计是对的，但闭环没有跑起来——知识网络目前对个性化毫无贡献。

#### D8（P1）大纲 summary 42% 为空，而它是提取的主要输入

622 个大纲条目中，**361 个（58%）有非空 `summary`**，平均 151 字符。

由于 D1（提取看不到正文），`outline[].summary` 成了模型做知识归纳的**唯一语义来源**。
42% 的章节连这个都没有，只剩标题。

**这解释了为什么概念定义普遍很短**（实测 `definition` 平均 50–70 字符）：
模型在只有标题和短摘要的情况下，写不出有信息量的定义。

#### D9（P1）硬约束声明最高优先级，却注入在提示词中段

`section()`（`prompts.py:834-877`）的块顺序（编号为注入位置）：

```
 1. 学科
 2. 学习目标
 3. 已学过章节
 4. 本章大纲
 5. 验收标准
 6. 【本次硬性约束块】        <-- 中段
 7. 生成挡位
 8. 能力层级
 9. 材料
10. 格式规范
11. 教学宪章                 <-- 优先级声明在这里
12. 教学决策
13. 配套文件名
14. 定向修正
15. 截断说明
16. 双链规则
17. 任务块
18. 输出 schema
19. 内容块规范
20. 元栏目禁令
```

`_teaching_charter`（`prompts.py:148-229`）内部声明优先级：
「系统与安全 > 硬性约束 > 本次任务特殊要求 > 教学导向 > 学习材料」。

**问题**：声明优先级的块在第 11 位，排在它要排序的「硬性约束」（第 6 位）**之后**。
而 *Lost in the Middle*（TACL 2024）的结论是长上下文中段利用率最低。

**修法**：把硬约束前移到第 2 位（学习目标之后），并在输出 schema 后（第 19 位之后）重申一次关键硬约束。
成本：几行代码改动。收益：待 A/B 验证。

#### D10（P2）缺执行接地：实践性教程的步骤从未被真正运行过

`COMPUTER_CLI` 学科画像（`disciplines.py:25-58`）要求：
- 每个命令给出前置条件、预期输出与验证方式；
- 示例可复制执行，并说明执行环境；
- 包含失败示例与排查步骤。

这些都是**提示词要求**，没有任何机制验证「示例真的能跑通」。
模型生成的命令、参数、预期输出全部来自语言模型的参数记忆，而非实际执行。

**From Task to Tutorial** 的核心差异就在这里：它的 Execution Agent 真的执行任务并采集轨迹。
AI Edu 不需要做到那个复杂度——一个最小可行版本是：
对 `COMPUTER_CLI` 目标的 `steps` 块，在沙箱里逐条运行命令、记录实际输出，
把「预期 vs 实际」的差异回传给模型修正（类似 `exam_verify.py` 的思路，但对象是命令而非题目）。

#### A1. 修复提取上下文的信息损失（修 F1 + D1 + D8）

**改什么**：`services\api\app\services\knowledge.py` 的 `_tutorial_context`（415–434 行）

**具体改法**：v2 章节的正文在 `content[]` 块里，按块类型分层取材：

```
def _tutorial_context(tutorial, version, *, max_chars=12000):
    content = jload(version.content_json, {}) if version else {}
    outline = content.get("outline", [])
    sections = content.get("sections", [])
    # 按块类型给权重：结构性知识块优先于普通文本
    WEIGHT = {"steps": 3.0, "method_summary": 2.5, "formula": 2.0, "key_point": 2.0,
              "table": 1.5, "comparison": 1.5, "diagram": 1.0, "note": 1.0, "example": 0.8, "text": 0.5}
    brief = []
    for s in sections:
        blocks = s.get("content") or []
        # 每个块取标题 + body 前 N 字符，按权重排序后截断到预算
        picked = []
        for b in blocks:
            if not isinstance(b, dict): continue
            w = WEIGHT.get(b.get("type", "text"), 0.5)
            picked.append((w, b.get("title", ""), str(b.get("body", ""))[:600]))
        picked.sort(key=lambda x: -x[0])
        digest, used = [], 0
        for w, t, body in picked:
            if used >= max_chars // max(1, len(sections)): break
            digest.append({"title": t, "excerpt": body[:400]})
            used += min(400, len(body))
        brief.append({
            "section_id": s.get("id", ""),
            "title": s.get("title", ""),
            "prerequisite_refs": [str(p) for p in s.get("prerequisite_refs", [])],
            "content_digest": digest,
        })
    return {
        "tutorial_title": tutorial.title,
        "outline": [{"section_id": o.get("id",""), "title": o.get("title",""),
                     "summary": o.get("summary","")} for o in outline],
        "sections": brief,
    }
```

**同时改**：`_stable_context`（438–459 行）同步读 `content_digest` 的标题，
否则正文重写后指纹不变、不会重新提取（D1 的衍生问题）。

**依据**：D1 实测（保留率 1.97%）；概念图生成综述（arXiv 2509.14554）指出概念图质量依赖输入文本的语义丰富度；
ProceduralKG（arXiv 2412.03589）要求从完整文本抽取，不能只看标题。

**验收**：改造后重跑 `extract_from_tutorial`，对比改造前后：
概念数、`related` 占比、`confirmed` 占比、`definition` 平均字符数。
预期 `related` 占比下降（模型有正文可依据，不再用兜底类型）、`definition` 变长。

**适用**：知识性教程 + 实践性教程（基础设施）。

统计每概念被提问次数，与 `mastery_for_concept` 的 `no_evidence` 概念取交集 → 高提问量 + 无掌握证据 = 高优先重讲。

**依据**：D7 实测（`attempts` = 0，掌握度闭环空转）；
Detecting Knowledge Gaps（arXiv 2606.10736）「提问量与自报难度显著相关，不需要题库」；
RPKT（arXiv 2508.11892）的「unknown unknowns」。

**验收**：`reflection` 输出的 `unresolved_gaps` 能对应到具体概念节点；
前端能展示「因反复提问而标记为待巩固」的概念。

**适用**：知识性教程 + 实践性教程。

#### C3. 块消融实验：确认每个注入块的真实价值（修 D9 的验证）

**改什么**：不改生产代码，写一个 `.audit\agent-research-2026-11-03\ablation.py` 实验脚本。

**依据**：EduQG Bloom Levels（arXiv 2408.04394）「信息过载显著降低质量」；
*Lost in the Middle*（TACL 2024）「中段利用率最低」。

## 5. 建议采纳的评测量规（可直接写进 `quality_report`）

### 5.1 知识性教程量规（源自 ELMES A.1 + A.3，适配 AI Edu）

**维度 1：知识准确性（Knowledge Mastery）**

| 指标 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 概念定义正确 | 有事实错误 | 基本正确但表述含糊 | 精确且给出成立条件 |
| 术语一致性 | 同一概念多个名称混用 | 基本一致 | 严格一致且与知识网络节点对齐 |
| 不编造 | 出现无依据的引用/网址 | 有「需核验」标注但过多 | 不确定处明确标注且数量克制 |

**维度 2：教学策略（Explanation Strategy）**

| 指标 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 直觉先于原理 | 直接给公式/定义 | 有直觉但弱 | 先建立问题背景与直觉，再给严格定义 |
| 原理推导完整 | 跳步 | 有关键步骤但缺依据 | 每步有依据，不跳步 |
| 适用条件明确 | 缺失 | 提到但不具体 | 明确列出边界与反例 |
| 与相关概念联系 | 缺失 | 简单罗列 | 有辨析（`contrasts_with`）与依赖（`prerequisite_of`） |

**维度 3：结构完整性（Structural Integrity，可确定性计算）**

| 指标 | 校验方式 |
|---|---|
| 验收标准双向覆盖 | `check_structure` 已有 |

**维度 4：个性化响应（Persona Responsiveness）**

| 指标 | 说明 |
|---|---|

## 6. 提示词层面的具体改法（可粘贴）

### 6.1 `knowledge_extract` 提示词改造

当前（`prompts.py:1040-1061`）要求模型输出 `concepts` 与 `relations`，
但**没有节点类型、没有层级、没有证据引文**。改造后的核心新增：

```
"从教程结构中提取结构化知识。要求：\n"
"- concepts：只提取教程结构直接体现的概念 / 学习单元；\n"
"  title 简明稳定；definition 一句话；\n"
"  **node_type** 只能取：concept（概念）/ skill（技能）/ tool（工具）/ fact（事实）\n"
"    / principle（原理）/ procedure（流程）/ exercise（练习）；\n"
"  **level** 取 1（章节级）/ 2（知识点级）/ 3（原子级）；\n"
"  section_id 指向最直接解释该概念的章节；已有概念（按名称）不要重复输出；\n"
"  最多 {cap_concepts} 个。\n"
"- relations：只写有依据的关系；from_title/to_title 必须能在 concepts 或已有概念中找到；\n"
"  relation_type 只能取 prerequisite_of / part_of / explains / applied_in / contrasts_with / related；\n"
"  **反对称约束**：同一对概念不允许在两个方向上有同类型关系——\n"
"    如果你判断 A 与 B 互为先修，请拆成两对不同的概念或改用 related；\n"
"  **证据引文**：rationale 必须引用教程正文或大纲中的关键短语（不超过 30 字），\n"
"    不能只写「A 是 B 的先修」这类同义反复；\n"
"  带 section_id 表示教程明确解释（会自动确认），纯推测则留空 section_id 并降低 confidence；\n"
"  不为图谱美观添加无依据的边；最多 {cap_relations} 条。\n"
```

关键变化：
1. **新增 `node_type` 与 `level`**：对齐 K12-KGraph 的 9 类节点思路，但收敛到 AI Edu 实际需要的 7 类；
2. **反对称约束写进提示词**：对应 ProPRL 的不可逆性约束，在生成端就阻止双向边；
3. **`rationale` 必须引用正文关键短语**：这是 A2「锚点可定位」的生成端配合——
   如果 `rationale` 里的短语在正文中找不到，自动降级为 `proposed`；
4. **上限动态化**：`{cap_concepts}` / `{cap_relations}` 由调用方传入（A5）。

### 6.2 `section` 提示词块顺序调整

**改动 1**：把 `_hard_constraints_section(goal)` 从当前的第 6 位前移到第 2 位：

```
user = (
    f"学科：{discipline.display_name}\n"
    f"学习目标：{json.dumps(_goal_ctx(goal), ensure_ascii=False)}\n"
    f"{_hard_constraints_section(goal)}"        # <-- 前移到这里
    f"已学过章节：{prior_titles}\n"
    f"本章大纲：{json.dumps(outline_for_prompt, ensure_ascii=False)}\n"
    # ... 其余块保持，但 _hard_constraints_section 从原位置移除
```

**改动 2**：在输出 schema 与内容块规范之后，追加尾部重申：

```
    + "\n硬性约束重申（交付前逐条自检，任一条不满足即本次交付不合格）：\n"
    + _hard_constraints_summary(goal)   # 新增：只输出约束原文清单，不带解释
```

**改动 3**：修正 `_teaching_charter` 中优先级声明的位置——把「系统与安全 > 硬性约束 > …」
这句话**前移**到 `_hard_constraints_section` 之前（或并入系统提示），
而不是在「教学宪章」块里才出现。

**改动 4（实践教程专属）**：`steps` 块的输出要求从纯 Markdown 改为结构化（B1），
提示词措辞：

```
"- steps：操作步骤。对实践教程，每个步骤必须给出：\n"
"  action（做什么）、object（对什么）、tool（用什么命令/工具）、\n"
"  expected_result（预期结果，必须是可观察的，不要写「成功」「正常」）、\n"
"  verification（怎么验证）、risk_level（observational / reversible / structural / administrative）、\n"
"  rollback（risk_level 为 structural 或 administrative 时必须给出回退方式）。\n"
"  按操作影响递增排序：先只读观察，再可逆操作，再结构性改动，最后系统管理。\n"
```

### 6.3 减少注入量的实验设计（C3 的操作说明）

不改生产代码，在 `_audit\agent-research-2026-11-03\` 写一个 `ablation.py`：

1. 选 5–10 个已有 `learning_goal`（覆盖不同 `domain_key` 与 `capability_level`）；
2. 对每个目标，用 7 个变体（full / no_charter / no_level / no_plan / no_companions / no_materials / reordered）各生成一章；
3. 用 §5.1 的量规，让一个**独立于生成模型**的评估模型打分；
4. 输出「块 × 维度」得分矩阵。

**判读标准**：如果去掉某块后质量分不降（甚至上升），说明该块是负资产，应从生产提示词中移除或按挡位裁剪。
预期 `no_materials` 在无上传材料时无影响（`_materials_section` 本来就返回空串），
而 `no_charter` 对硬约束遵守率的影响是关键观测点。

   文献已经给出方向（过度注入有害），但你的 11 个块里具体哪些有害，只有实验能回答。
5. **C1（执行接地）是实践性教程的终局方向**，但工程量大，建议在 B1/B4 稳定后再启动。
