## 1. 项目全景与架构概述

### 1.1 核心定位

AI Edu 是一个**本地优先、单用户**的 AI 辅助学习系统。它不是「又一个教程收集器」，而是把一条强约束的学习方法论固化成软件流程：

> **先明确要解决的问题 → 先定义「学会的证据」→ 再生成教程**

这条理念直接体现在代码结构上，而不只是文案：

| 理念 | 代码落点 |
|---|---|
| 先判断值不值得学 | `pipeline.quickstart()` 在生成前跑价值诊断，AI 判定不值得时抛 `409 generation_paused`，**必须由用户选择**才继续 |
| 先定验收标准 | `start_sections()` 调 `_criteria_list()` 校验，无已确认标准直接 `409`；大纲不采信模型自拟结构 |
| 证据可核验 | `engine.check_structure()` 做 5 项确定性检查，含「验收标准双向覆盖」 |
| 不伪造模型输出 | 未配置模型时进入演示模式，响应显式标 `demo: true`；token 无 usage 时标 `usage_source: estimated` |
| 生成内容需核验 | `service._rule_checked()` 对输出跑机器可核验的禁止性约束，违规则定向重写一次，并如实记录 `rule_check` |

### 1.3 三个关键架构决策

**① 同源代理，不做 CORS 直连。** 浏览器只访问 `127.0.0.1:3001/api/*`，由 Next 服务端转发到 8000。规避了系统代理/跨源策略拦截本地请求的问题，也让 `proxyTimeout: 3_600_000` 能覆盖长达 1 小时的深度生成。

**② 确定性规则优先于「让模型自觉」。** 最典型的是 `delivery_contract`（交付契约）：当用户硬约束里出现「只包括 A、B、C」这类组成型规定时，`_contract_outline()` **不采信模型大纲**，直接用清单构造章节（一个交付物一章），模型只负责把每章写成那一项成品。理由见 ADR-018：提示词能约束语气详略，约束不了交付物由哪几项组成。

**③ 后台任务 + 幂等，而非同步长请求。** 章节生成、配套文件、知识提取都在后台线程跑，接口立即返回 `job_id`。幂等保护做得比较扎实：同一目标已有 `queued/running` 的章节任务时直接复用（`start_sections` 返回 `reused: True`），连点不会重复计费。

### 3.2 数据流：一次模型调用的三重落库

```
AIService._real_json(feature, system, user, required, goal)
  │
  ├─ provider.complete_json(system, user)
  │    └─ httpx.post → 解析 choices[0].message.content
  │         ├─ JSON 解析失败 → llm/ 的修复链（截断补全/围栏剥离/尾逗号清理）
  │         └─ usage 缺失 → estimate_usage() 按字符估算，标 usage_source="estimated"
  │
  ├─ _record(feature, system, user, output, usage, goal)
  │    ├─ ModelCallLog      ← token 统计的唯一来源（goal/tutorial/job 关联）
  │    └─ TrainingRecord    ← 训练样本（system+user prompt + 输出 + 元数据 + context_json）
  │         context_json 里存 goal_id/goal_title/domain_key/tutorial_id/section_id/demo
  │
  └─ 失败路径：_log_error() 只写 ModelCallLog(status="error")，**不产生训练样本**

下游消费者：
  ModelCallLog  → services/usage.py:goal_usage() → /api/goals/{id}/usage → 前端 token 展示
  TrainingRecord→ services/training.py           → /api/training/*        → 测试数据页 + JSONL 导出
```

### 3.3 三条贯穿全局的设计约束

**① 并发安全靠「每任务独立 Session」，不靠共享。** `_run_parallel_initial_tasks`、`_generate_section_task`、`_companion_task`、`_knowledge_extraction_worker` 全部自己 `SessionLocal()` + 自己 `AIService(db, goal_id=...)`。SQLite 短事务尽快释放写锁（`PRAGMA busy_timeout=30000`）。

**② 快照冻结，避免「生成中途模板被改」。** 格式规范在大纲前解析成 `format_spec_snapshot` 存进 goal；后台章节任务只读快照。`format_specs.authoritative_snapshot()` 判断快照是否真正接管模板。

**③ 路径全部锚定 `BACKEND_ROOT`。** `config.py` 的 `_resolve_path()` 把数据库/材料/备份目录都锚到 `services/api/`，从任何目录启动都指向同一份数据。**本次审计发现三处漏网**（见 `PROJECT_AUDIT.md` 问题 A/B），已修复。

## 4. 高阶推荐用法与实战场景

### 场景 1：用「交付契约」让 AI 产出成品而非讲解（最有价值的能力）

**痛点**：你要的是一份可直接用的试卷，AI 却给你 6 章 6.4 万字的讲解教程，试卷只占一章。

**原理**：`teaching_profile.parse_teaching_profile()` 把画像里的**条件规则**按目标文本求值（`rule_is_active`），命中后 `delivery_contract_for()` 从生效硬约束里抽出「只包括…」的清单项与「不要…答案」标志。`tutorials._contract_outline()` 随即**放弃模型大纲**，用清单直接构造章节，章节提示词切成「交付物模式」，并抑制知识速查/额外练习。

**操作**：偏好设置 → 用户画像，写入条件规则（注意「当…的时候」句式 + 「务必/不要」情态词）：

```
当「学完想能做什么」中出现「输出试卷」的时候，务必模仿参考资料输出标准试卷，
且内容只包括对真题风格的简要分析、三套模拟试卷和对压轴题的 3 个合理拓展，
不要输出答案及其它内容
```

然后创建目标时，在「学完要能做什么」里写「完成你输出的试卷」，并上传真题作为**例题来源**。

**验证是否生效**：`GET /api/tutorials/{id}` 看 `current_version.content.delivery_contract`（随版本落库，可解释可回溯）；章节标题应逐字等于交付物名称。

> 触发词做了虚词归一（去掉「的/了/你」），所以「完成你**输出的**试卷」能命中「输出试卷」。

### 场景 2：把已有资料变成教程，并核验材料真的进了 prompt

```powershell
# 1. 创建目标并上传参考资料（分类：reference / example_source）
curl -X POST http://127.0.0.1:8000/api/goals -H "Content-Type: application/json" `
  -d '{"title":"线性代数期中冲刺","domain_key":"math_logic","capability_level":"L3","generation_tier":"standard"}'

curl -X POST http://127.0.0.1:8000/api/goals/{GID}/materials `
  -F "file=@考试范围.pdf" -F "kind=reference" -F "note=期中范围"

# 2. 触发一键生成
curl -X POST http://127.0.0.1:8000/api/goals/{GID}/tutorials/quickstart

# 3. 核验材料确实注入了 prompt（不是「代码支持」而是「实际发生」）

```

第 3 步返回的 `prompt_preview` 里能直接看到材料原文片段；`output_chars` 与 `total_tokens` 说明注入规模。若材料超预算，`materials_context` 会**明确标注截断状态**而非静默丢弃。

调预算：`.env` 里 `MATERIAL_PROMPT_PER_FILE_CHARS` / `MATERIAL_PROMPT_TOTAL_CHARS`（默认 0 = 不额外截断，全文注入）。

### 场景 3：导出训练数据做微调，且能区分「真实模型」与「演示数据」

```powershell
# 只导真实模型产出的样本（排除 demo=true）
curl -OJ "http://127.0.0.1:8000/api/training/export?fmt=jsonl&exclude_demo=true"

# 按目标导（便于单课题微调）
curl -OJ "http://127.0.0.1:8000/api/training/export?goal_id={GID}&source_type=material"
```

JSONL 每行是标准指令微调样本：

```json
{"id":"...","source_type":"material","feature":"section","created_at":"...",
 "messages":[{"role":"system","content":"..."},{"role":"user","content":"..."},
             {"role":"assistant","content":"..."}],
 "metadata":{"goal_id":"...","model_name":"deepseek-flash","total_tokens":38123,
             "usage_source":"provider","demo":false,"context":{...}}}
```

**实战技巧**：`metadata.usage_source == "provider"` 的样本才是真实模型产出；`"estimated"` 说明当时没拿到 usage。配合 `feedback` 类样本（`rating: 1/-1` + `tags` + `comment`）可做偏好对齐数据。网页「测试数据」页的「按功能分布」能直接看出哪个阶段最烧 token（实测：章节生成 5.35M / 知识提取 1.10M / 速查 489k）。

### 场景 4：生成中断后不丢内容，且不会重复烧钱

系统在三个层面防重复计费，值得了解以便放心离开页面：

1. **任务级幂等**：`start_sections` / `start_companions` 发现同目标已有 `queued/running` 任务时直接复用 `job_id`，返回 `reused: True`。连点无效。
2. **章节级重试**：`_section_with_retry` 遇超时/限流/截断按 `(3, 8)` 秒退避重试两次，原因写进 `job.stage` 与 `retry_count`；失败后已完成章节保留为草稿版本。
3. **自动续跑闸门**：`lib/tutorial-continue.ts` 只在「大纲生成于 30 分钟内且无任何章节」时自动续跑，且**每目标每标签页只自动尝试一次**——避免模型持续报错时每次刷新都提交一整轮章节生成。你主动点过「只生成大纲」的话，`sessionStorage` 会记住这个选择，自动续跑不再推翻它。

服务重启也不会永久转圈：`main.py:_sweep_stale_jobs()` 在 lifespan 里把上次进程中断遗留的 `queued/running` 任务标为 `failed` + `error_code="server_restart"`。

### 场景 5：Obsidian 插件做「生成即归档」的闭环

插件（`obsidian-plugin/ai-edu-tutorial-delivery/main.js`，1213 行）不是简单的导出按钮，而是一条独立交付链：

```
插件表单（与网页同字段）
  → 无材料：POST /api/goals/quickstart
  → 有材料：POST /api/goals → 逐个上传 /materials → POST /goals/{id}/tutorials/quickstart
            （材料上传失败不重复创建目标，重试只补传材料）
  → 轮询 /api/generation-jobs/{id}
  → 拉 /api/tutorials/{id}/export（主教程）+ export/cheatsheet + export/exercises
  → 写入 Vault；重名时统一追加 v2/v3 后缀，并同步改写三者内部双链（不覆盖已有笔记）
  → 校验双链：未解析链接在通知里列出
  → POST /api/tutorials/{id}/delivery {status:"delivered", path, version}  回写交付状态
```

可独立测试（不依赖 Obsidian 运行时，覆盖 7 类行为）：

```powershell

```

### 场景 6（创新性用法）：把质量检查当「教程回归测试」用

`engine.check_structure()` 是纯函数，输入 `(content, criteria)`，输出 5 项检查 + 双向覆盖统计。可以脱离 Web 直接用它批量体检已有教程：

```python
import sqlite3, json, sys
sys.path.insert(0, r"D:\桌面\dsh\ai-edu\services\api")
from app.learning.engine import check_structure

db = sqlite3.connect(r"D:\桌面\dsh\ai-edu\services\api\data\aiedu.db")
db.row_factory = sqlite3.Row
for row in db.execute("""
    SELECT t.id, t.title, tv.content_json, tv.version
    FROM tutorials t JOIN tutorial_versions tv ON tv.id = t.current_version_id
"""):
    content = json.loads(row["content_json"])
    crits = [{"id": c["id"], "statement": c["statement"]} for c in
             db.execute("SELECT id, statement FROM acceptance_criteria WHERE goal_id="
                        "(SELECT goal_id FROM tutorials WHERE id=?) AND status='confirmed'",
                        (row["id"],))]
    report = check_structure(content, crits)
    print(f"{'OK ' if report['passed'] else 'BAD'} v{row['version']} {row['title'][:30]}")
    for issue in report["issues"]:
        print("      -", issue)
```

这能一次性找出「哪些历史教程的验收标准没被章节覆盖」「哪些章节正文为空」，比逐个点开网页快得多。改提示词或换模型后重跑，就是教程质量的回归基线。
